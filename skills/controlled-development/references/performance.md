# 性能优化方案

适用于以耗时、吞吐或资源使用改善为目标的改动。先确定可比较的基线、目标和测量条件，不凭代码表象宣称变快。

## 基线与瓶颈

- 说明受影响用户和入口，记录当前指标、样本规模、负载、环境及目标值。区分监控、调用链、查询计划或分析器证明的瓶颈与推测。
- 给出关键改动及预期收益；涉及 SQL 或索引时结合 [SQL 与性能检查](sql-review.md) 说明访问模式、执行计划和新增索引的写入/存储代价。

## 影响、风险与验证

- 涉及缓存或并发时说明一致性、失效和资源上限。列出入口、业务规则、数据库、缓存、配置及预计文件。
- 评估结果错误、数据过期、峰值退化、资源成本转移和新旧行为差异；缺少测量条件或业务口径时列疑问。
- 在可比较条件下对照优化前后指标，同时检查功能结果、关键边界和资源消耗。无法取得目标规模证据时只报告已测范围。
