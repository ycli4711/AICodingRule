# 方案展示与交付

依据任务规模组织短段、表格或图，不逐栏照抄通用栏目；所选场景的最小核心表或清单仍须完整展示。已在会话中确认的口径直接沿用。局部且行为明确的修复可简述目标、影响与验证；复杂方案按以下骨架组织。一个任务跨场景时合并对应核心内容，不重复通用栏目。表格前后留空行，标题、字段表和时序图各自成段；表格只放短字段和值，较长规则移到表后的编号列表，不用横向很宽的表或密集长段承载全部信息。

## 实施前方案

按用户级 AGENTS.md 的回复结构展示。需要实施确认且尚未写入时，在 [直接执行] 开头独立写 📋 **待授权实施**，并在 [深度交互] 末尾独立写 ✋ **待你确认**，下一段明确本次待授权范围。发出后结束本轮并等待用户回应，不在同一轮继续写入；先前已确认同一具体方案时才省略确认。只读核查不称为“部分完成”，尚无文件变更时只列预计文件。标签单独成段，标签与内容之间留空行。

在 [直接执行] 下依次给出：

1. **业务目标与完成标准**：当前事实、目标行为、关键规则；推断与待定口径明确标注。
2. **场景核心产物**：接口契约与时序、状态转换表、Bug 根因、数据库变更、异步交互、性能基线、行为对照或页面状态，按主场景及实际涉及的附加场景选择。图、伪代码、伪 SQL 只在有助于说明关键顺序、判断或数据访问时给出；接口开发遵循其场景要求。
3. **实施步骤**：按依赖顺序说明要查、改、验证什么；区分代码或 SQL 文件、隔离测试、真实数据操作及外部调用。
4. **影响范围**：入口与调用方、接口契约、状态与数据、权限、缓存、外部系统、页面及预计文件中适用的部分；相关旁路分别标明需改、已核实无需改或待核实。
5. **风险点与疑问**：风险写触发条件、后果和应对；疑问写缺少的业务口径、影响哪个决定及推荐选项。没有实质风险或疑问时简述评估结论，不编造问题。会影响正确性、授权或重要副作用的疑问须在相关操作前提出。
6. **验证计划与边界**：正常、失败和关键边界如何检查；区分可在当前环境验证与需要目标环境证据的结论。

仅当存在实质取舍或需用户回应时，在 [深度交互] 放推荐方案、待选择项、待澄清口径或实施授权。业务口径和授权分别提问；已获授权不重复索取。新增接口或改变对外契约的方案先写共同业务目标，再按接口独立成节，各节展示 URL/方法、适用的请求与响应变更、错误结果、时序及核心逻辑；最后统一列实施步骤、影响范围、风险与疑问、验证计划。接口总览只能作索引，不得代替逐接口契约与流程。

若现有接口的 URL/方法、请求与响应结构、校验、错误结果及权限均不变，只改变内部规则、默认取值或处理流程，按实际主场景写方案：先说明目标与原有结果，再列真正要改的规则/代码链、受影响入口的可见结果差异、外部副作用和验证。对未改契约写一句已核实的保持范围；只对变化的现有字段说明旧值与新值，不重列完整入参/出参、权限和每个接口的时序图。受影响入口不等于各入口均需改代码，分别标明“需修改 / 只受影响 / 已核实无需改”。跨模块或异步顺序重要时，可用一张业务链时序图说明关键顺序。方案细致程度和实施确认仍按业务风险决定，不因省略重复契约而跳过高风险副作用审查。

发出实施确认前，按所选场景核对核心产物是否能让用户逐项判断：状态转换、数据操作、外部调用/事件、性能指标、重构入口或页面操作各自有独立行；复杂 Bug 的现象、根因、修复与回归各有明确条目。关键字段、条件、结果、证据和未核实项能否对应到具体行；图与列表、SQL 是否一致；影响、风险、疑问和验证是否与产物相连。缺少会改变行为或授权范围的证据时先继续只读核查或澄清，不把笼统摘要当作完整方案请求整项确认。简单且行为明确的修复不为此填空表。

需要新增或改变的接口响应采用逐字段表格，嵌套字段写完整路径；本次变化的请求和响应字段不能用一句逗号或顿号分隔的清单代替。时序图只说明参与者和顺序，图后的筛选、排序、分页、回显等独立规则用编号列表说明，必要的伪 SQL 单独成块；实施、验证和未验证限制再分段展示。

页面开发与联调方案先列交互核查清单，再用简短总览表对应页面模块、触发操作和接口 URL/方式；每个模块独立小节，分别用请求映射表和响应映射表逐字段对应页面内容、请求来源和响应路径，最后逐模块说明可实际联调的范围。会影响页面范围或信息展示的原型/接口差异先作为业务选择提出；取得口径后更新方案，再请求实施确认。不能把未核查交互、自行删减的字段或未映射的模块包装进一次笼统的“按方案实施”确认。

## 数据和环境边界

- 新建/修改表、字段、约束或索引，以及预置、批量插入/更新/删除数据，单列结构或数据变化、目标环境、预计及允许影响范围、执行顺序、重复执行和恢复依据；读取 [数据库结构与数据](database-change.md) 与 [SQL 与性能检查](sql-review.md)。
- 真实数据修复说明精确选取条件、只读预览数量及脱敏样本、变更字段与计算规则、事务或分批方式、并发漂移检测和停止条件。预览与执行之间数据可能变化，执行对象必须仍符合前置条件。报告已提交批次，不把局部成功称为全部完成。
- 编写迁移文件、隔离验证、目标库执行以及真实业务接口调用是不同操作；明确各自授权和验证状态。

## 交付核对

用简短清单核对计划行为、实际行为、证据和有业务含义的差异。报告实际文件、数据和外部操作范围，保留剩余风险、疑问及未完成项的原因与下一步。已解决问题从待处理项移除；写入成功、编译通过或模拟测试均不自动代表完整业务验收。
