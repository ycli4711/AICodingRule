# 方案展示与交付

依据任务规模组织短段、表格或图，不逐栏照抄。已在会话中确认的口径直接沿用。局部且行为明确的修复可简述目标、影响与验证；复杂方案按以下骨架组织。一个任务跨场景时合并对应核心内容，不重复通用栏目。

## 实施前方案

按用户级 AGENTS.md 的回复结构展示。需要实施确认且尚未写入时，在 [直接执行] 开头独立写 📋 **待授权实施**，并在 [深度交互] 末尾独立写 ✋ **待你确认**，下一段明确本次待授权范围。发出后结束本轮并等待用户回应，不在同一轮继续写入；先前已确认同一具体方案时才省略确认。只读核查不称为“部分完成”，尚无文件变更时只列预计文件。标签单独成段，标签与内容之间留空行。

在 [直接执行] 下依次给出：

1. **业务目标与完成标准**：当前事实、目标行为、关键规则；推断与待定口径明确标注。
2. **场景核心产物**：接口契约与时序、状态转换表、Bug 根因、数据库变更、异步交互、性能基线、行为对照或页面状态，按主场景及实际涉及的附加场景选择。图、伪代码、伪 SQL 只在有助于说明关键顺序、判断或数据访问时给出；接口开发遵循其场景要求。
3. **实施步骤**：按依赖顺序说明要查、改、验证什么；区分代码或 SQL 文件、隔离测试、真实数据操作及外部调用。
4. **影响范围**：入口与调用方、接口契约、状态与数据、权限、缓存、外部系统、页面及预计文件中适用的部分；相关旁路分别标明需改、已核实无需改或待核实。
5. **风险点与疑问**：风险写触发条件、后果和应对；疑问写缺少的业务口径、影响哪个决定及推荐选项。没有实质风险或疑问时简述评估结论，不编造问题。会影响正确性、授权或重要副作用的疑问须在相关操作前提出。
6. **验证计划与边界**：正常、失败和关键边界如何检查；区分可在当前环境验证与需要目标环境证据的结论。

仅当存在实质取舍或需用户回应时，在 [深度交互] 放推荐方案、待选择项、待澄清口径或实施授权。业务口径和授权分别提问；已获授权不重复索取。复杂接口方案按业务目标、接口契约、业务时序、核心伪代码/SQL、实施步骤、影响范围、风险与疑问、验证计划分段；不适用项简述原因或省略，不得以一段目标摘要和一张时序图替代契约表与影响评估。

接口响应采用逐字段表格，嵌套字段写完整路径；请求和响应字段不能用一句逗号或顿号分隔的清单代替。时序图只说明参与者和顺序，图后的筛选、排序、分页、回显等独立规则用编号列表说明，必要的伪 SQL 单独成块；实施、验证和未验证限制再分段展示。

依据可交互原型的页面方案，先列交互核查清单与页面操作到接口、响应和页面结果的对应关系，再请求实施确认。会影响页面范围或信息展示的原型/接口差异先作为业务选择提出；取得口径后更新方案，再请求实施确认。不能把未核查交互或自行删减的字段包装进一次笼统的“按方案实施”确认。

## 数据和环境边界

- 新建/修改表、字段、约束或索引，以及预置、批量插入/更新/删除数据，单列结构或数据变化、目标环境、预计及允许影响范围、执行顺序、重复执行和恢复依据；读取 [数据库结构与数据](database-change.md) 与 [SQL 与性能检查](sql-review.md)。
- 真实数据修复说明精确选取条件、只读预览数量及脱敏样本、变更字段与计算规则、事务或分批方式、并发漂移检测和停止条件。预览与执行之间数据可能变化，执行对象必须仍符合前置条件。报告已提交批次，不把局部成功称为全部完成。
- 编写迁移文件、隔离验证、目标库执行以及真实业务接口调用是不同操作；明确各自授权和验证状态。

## 交付核对

用简短清单核对计划行为、实际行为、证据和有业务含义的差异。报告实际文件、数据和外部操作范围，保留剩余风险、疑问及未完成项的原因与下一步。已解决问题从待处理项移除；写入成功、编译通过或模拟测试均不自动代表完整业务验收。
