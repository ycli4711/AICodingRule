# 执行协作

授权以 [方案与授权](feature-design.md#唯一授权规则) 为唯一依据；本文件只规定执行方法。主控和子代理均须按实际仓库工作，不把通用规则替代项目规范。

## 各仓库规范加载与落实

从用户路径、当前目录、有效记录或宿主项目清单核实工程身份，不从截图猜路径。记录各仓库分支/提交、已有改动及必要文件基线。命令明确工作目录，工具与 MCP 能力实际核验，不假定跨仓库共享配置。

执行者自行读取目标路径适用的上级、根目录和子目录 AGENTS.md 及相关语言工程规范。主控摘要和历史代码不能替代规范；同一执行者已读且未变化的内容无需重复加载。进入新路径或规范变化时补读。引用缺失或冲突先核查，只暂停确受影响的部分；不声称读过缺失资料。

仅记录影响当前变更的约束与来源。具体架构、类型、注释、文件组织和工具链属于项目，不复制进通用 Skill；旧违规不构成例外。

## 只读核查与任务关联性

涉及方案正确性的现有接口、配置或数据库事实，应在请求实施授权前完成必要的只读核查；不能只把尚未做的检查写为“实施后再核实”。优先复用仍有效的证据，范围限于目标行为及直接依赖，不扩大成环境巡检。

数据库优先使用已配置 MCP；没有可用 MCP 不等于数据库不可连接。继续核对项目实际开发配置、环境覆盖和已有连接记录，并使用现有可用客户端或驱动尝试最小只读连接；核对目标身份、相关表字段、索引及必要迁移状态。凭据只在本地使用，不输出到日志、文档或命令回显。目标不明确、缺凭据或需新增工具时先说明具体缺口，不猜测生产目标、不擅自安装依赖或绕过访问限制。

严格区分“尚未尝试”“尝试失败”和“连接成功但部分查询受限”。只有实际失败或明确限制才报告阻塞，并给出已尝试方式、脱敏错误、影响范围和解除条件；没有连接尝试不能宣称无法访问，也不能因写 SQL 需授权就停止已授权只读核查。读取成功后将发现回写方案、修正不成立的设计，并移除失效阻塞；只改措辞而不补核查不算解决。

只读查询不授权建表、迁移、初始化或清理数据。沿用用户保留的数据库手动执行关口，不能用测试、迁移工具或应用调用代替批准边界。证据已足够时停止，不为证明可连接而反复查询业务数据。

## 分支与运行环境

以下任务分支/worktree 默认安排仅适用于用户明确启用 `feature-delivery-workflow` 且已获实施授权的正式开发。未明确启用主技能、仅分析或编写方案、单独使用配套角色、读取或修改技能，都不触发该安排。启用边界用于防止普通任务自动切分支，不能据此把已启用工作流的正式开发改成默认使用主目录。

方案记录各仓库真实开发基线分支及提交、已有改动和交付方式。正式写业务代码前，默认创建或复用本任务独立 worktree，并使用从已核实开发基线建立的任务分支；不在主目录切分支代替独立工作树。单任务、没有并发冲突或前后端分属不同仓库，都不取消这个默认安排。跨仓库开发分别隔离各个需要写入的仓库；只读参考仓库无需创建。优先复用属于本任务且基线、改动归属适合的已有工作树，不重复创建。

主目录开发仅作为有明确理由的例外，例如用户明确要求在原目录开发，或已核实非 Git、工具限制等使 worktree 无法使用。实施前在方案中简述具体原因、为何不能采用或复用独立工作树、受影响仓库、并发/改动混入风险及保护措施；不能只写“复用主目录”。单纯为了方便、只有一个任务、主目录已有未提交改动，都不足以构成例外。必要依赖优先按下文的补丁或文件清单带入工作树；确实不能安全隔离时说明具体障碍，不能静默回退主目录。已有授权覆盖的常规隔离安排直接执行，例外涉及新增风险、授权范围或用户偏好冲突时才集中确认。

规则更新不自动迁移正在开发的任务。继续前核对当前改动和执行者，记录继续使用主目录的具体例外依据，或准备安全迁移安排；不得仅以“已经开始”作为永久例外，也不得在其他执行者仍写入时搬迁、切换目录或复制不明归属的修改。

新建手动 worktree 默认放在主记录目录 `.codex/workflows/<任务标识>/worktree/`；跨仓库任务在同一主记录目录使用 `worktrees/<仓库标识>/`，分别绑定各自仓库，不能混放代码。记录文件和 evidence 放在工作树外，与代码目录同级，删除代码时保留记录。使用 Git 创建，不能用整库复制代替；宿主管理的已有工作树沿用其位置及生命周期工具，在主记录中保存路径，不强行搬入任务目录。

创建前确认路径未占用，并核查嵌套目录的排除条件：让主仓库忽略实际 worktree 路径，优先使用本地 `.git/info/exclude`，团队共享规则按项目约定维护 `.gitignore`；核查构建、测试、搜索和文件监听的实际扫描范围，Git 忽略不能代替工具排除。所需构建配置变化须纳入方案，不能静默扩大改动；排除条件无法满足时说明原因并采用已确认的外部隔离位置。

新 worktree 不带原目录未提交内容；核对归属和依赖后，仅用可验证补丁或文件清单带入必要内容。排除 `.codex/workflows`、`.git`、依赖和构建产物，避免递归复制任务目录；保留原目录，不硬重置、自动 stash 或移动用户改动。依赖优先独立安装并复用包管理器缓存，不默认联接主目录 node_modules；确需联接时记录链接路径、真实目标及清理方式。

从任务目录以独立端口启动服务，核对浏览器、代理及 API 实际指向本分支。复用已确认的共享开发数据库和 Redis，不强制另建数据环境或隔离消费者；仍核实实际后台副作用不超出授权。任务代码与端口独立不代表数据隔离。记录本任务进程身份，不能停止其他任务进程或抢占端口。

正式业务开发向开发基线整合前，必须满足 [人工验收关口](acceptance.md#工程完成与人工验收)；文件复制、补丁应用及增量回写与 Git 合并受同一关口约束。

合并默认回到已核实的开发基线，不用当前恰好检出的分支代替。方式沿用仓库约定；无约定时保留历史，能快进则快进，否则普通合并。不为常规分支和方式重复提问，有歧义或影响其他工作时才集中处理。

## 分派与并行

角色不是固定团队人数。前后端或其他任务具备独立输入、写入边界且工具允许时并行；小任务由主控承担。默认聚焦一个功能不等于一个执行者。不同仓库不必独立，同仓库也不必串行；共享文件、构建目录及会相互干扰的运行资源指定唯一写入或操作负责人。

区分开发依赖与联调依赖：契约明确后可独立实现的部分先做；运行接口、实际 Schema 等条件只阻塞依赖它的接入或验证。项目强制的契约核验前置条件须遵守，不借 Mock 绕过。契约可核对就及时交接，不等待无关测试；文档就绪不等于真实业务可用。

简报给出目标、目录、角色 Skill、项目规范路径、有效方案及授权依据、原有改动、写入边界、依赖和完成条件。子任务不递归组建工作流，不能凭别的案例猜本任务。角色交接只报告有变化的事实及证据，主控维护公共记录。

只要操作互不干扰即可并行，不要求数据库实例物理隔离。共享浏览器、可冲突的账号/数据、构建输出和 Git 写操作由唯一负责人处理。审核和行为验证可在明确版本上并行；代码变化只使受影响证据失效。

独立侧栏会话仅在用户明确授权后创建或发消息，内部代理授权不能替代。使用实际工具能力，通知送达与执行完成分开核实；失效任务 ID 不反复联系。

## 执行效率

- 开始时最小核查服务、文档与构建条件，不默认全量构建。隔离目录和可靠缓存可复用，变化时核对版本，不反复复制整库。
- 确需清洁构建时先核对服务/构建进程对输出目录的占用；确认本任务身份和无后续依赖后停止并核实退出，不按进程名批量终止。有效构建证据仍适用时不为收尾再次 clean。
- 同一输出目录由一人构建，其余执行者复用有效证据。等待采用完成通知或适当间隔查询，不频繁读取相同日志；耗时异常区分有效推进、失败和停滞，不任意限时中断。
- 准备提交时可并行：主控核对证据和简短交付记录，子代理只读核对文件归属、基线、目标变化及冲突风险。主控统一串行暂存、提交、合并，并在写操作前核对版本未失效；不为小任务强制新增代理。

## 阻塞处理

不能只列遗留项结束。核实具体原因与证据，继续独立已授权工作；可安全解除的直接处理，需要增量授权或信息时按 [授权规则](feature-design.md#唯一授权规则) 准备具体步骤与影响并明确提出，不只写“待授权”。

区分代码、文档、环境版本、工具和权限缺口；搜索不到接口不能直接推导必须部署。记录下一步责任、解除条件与恢复点。用户补充后核对当前状态续做，不重做仍有效项。重复故障无进展时重新定位原因；写操作结果未知先查是否生效，不盲目重试。不自行设置修复轮数或时间预算，用户已有预算才按约定处理。

恢复只核对有效范围与授权、实际代码及新改动、证据有效性、真实执行者状态和剩余最小任务。无证据不得宣称完成；结束会话后不承诺自动唤醒。
