# 执行协作

授权以 [方案与授权](feature-design.md#唯一授权规则) 为唯一依据；本文件只规定执行方法。主控和子代理均须按实际仓库工作，不把通用规则替代项目规范。

## 各仓库规范加载与落实

从用户路径、当前目录、有效记录或宿主项目清单核实工程身份，不从截图猜路径。记录各仓库分支/提交、已有改动及必要文件基线。命令明确工作目录，工具与 MCP 能力实际核验，不假定跨仓库共享配置。

执行者自行读取目标路径适用的上级、根目录和子目录 AGENTS.md 及相关语言工程规范。主控摘要和历史代码不能替代规范；同一执行者已读且未变化的内容无需重复加载。进入新路径或规范变化时补读。引用缺失或冲突先核查，只暂停确受影响的部分；不声称读过缺失资料。

仅记录影响当前变更的约束与来源。具体架构、类型、注释、文件组织和工具链属于项目，不复制进通用 Skill；旧违规不构成例外。

## 分支与运行环境

方案记录各仓库真实开发基线分支及提交，实施确认后、写代码前创建或复用本任务独立分支/worktree。非 Git 或工具不可用时说明限制，采用已确认替代方案。新 worktree 不带原目录未提交内容；先核对归属和依赖，仅用可验证补丁或副本带入必需内容，保留原目录，不硬重置、自动 stash 或移动用户改动。不为新规则重做进行中的开发。

从任务目录以独立端口启动服务，核对浏览器、代理及 API 实际指向本分支。复用已确认的共享开发数据库和 Redis，不强制另建数据环境或隔离消费者；仍核实实际后台副作用不超出授权。任务代码与端口独立不代表数据隔离。记录本任务进程身份，不能停止其他任务进程或抢占端口。

合并默认回到已核实的开发基线，不用当前恰好检出的分支代替。方式沿用仓库约定；无约定时保留历史，能快进则快进，否则普通合并。不为常规分支和方式重复提问，有歧义或影响其他工作时才集中处理。

## 分派与并行

角色不是固定团队人数。前后端或其他任务具备独立输入、写入边界且工具允许时并行；小任务由主控承担。默认聚焦一个功能不等于一个执行者。不同仓库不必独立，同仓库也不必串行；共享文件、构建目录及会相互干扰的运行资源指定唯一写入或操作负责人。

区分开发依赖与联调依赖：契约明确后可独立实现的部分先做；运行接口、实际 Schema 等条件只阻塞依赖它的接入或验证。项目强制的契约核验前置条件须遵守，不借 Mock 绕过。契约可核对就及时交接，不等待无关测试；文档就绪不等于真实业务可用。

简报给出目标、目录、角色 Skill、项目规范路径、有效方案及授权依据、原有改动、写入边界、依赖和完成条件。子任务不递归组建工作流，不能凭别的案例猜本任务。角色交接只报告有变化的事实及证据，主控维护公共记录。

只要操作互不干扰即可并行，不要求数据库实例物理隔离。共享浏览器、可冲突的账号/数据、构建输出和 Git 写操作由唯一负责人处理。审核和行为验证可在明确版本上并行；代码变化只使受影响证据失效。

独立侧栏会话仅在用户明确授权后创建或发消息，内部代理授权不能替代。使用实际工具能力，通知送达与执行完成分开核实；失效任务 ID 不反复联系。

## 执行效率

- 开始时最小核查服务、文档与构建条件，不默认全量构建。隔离目录和可靠缓存可复用，变化时核对版本，不反复复制整库。
- 确需清洁构建时先核对服务/构建进程对输出目录的占用；确认本任务身份和无后续依赖后停止并核实退出，不按进程名批量终止。有效构建证据仍适用时不为收尾再次 clean。
- 同一输出目录由一人构建，其余执行者复用有效证据。等待采用完成通知或适当间隔查询，不频繁读取相同日志；耗时异常区分有效推进、失败和停滞，不任意限时中断。
- 准备提交时可并行：主控核对证据和简短交付记录，子代理只读核对文件归属、基线、目标变化及冲突风险。主控统一串行暂存、提交、合并，并在写操作前核对版本未失效；不为小任务强制新增代理。

## 阻塞处理

不能只列遗留项结束。核实具体原因与证据，继续独立已授权工作；可安全解除的直接处理，需要增量授权或信息时按 [授权规则](feature-design.md#唯一授权规则) 准备具体步骤与影响并明确提出，不只写“待授权”。

区分代码、文档、环境版本、工具和权限缺口；搜索不到接口不能直接推导必须部署。记录下一步责任、解除条件与恢复点。用户补充后核对当前状态续做，不重做仍有效项。重复故障无进展时重新定位原因；写操作结果未知先查是否生效，不盲目重试。不自行设置修复轮数或时间预算，用户已有预算才按约定处理。

恢复只核对有效范围与授权、实际代码及新改动、证据有效性、真实执行者状态和剩余最小任务。无证据不得宣称完成；结束会话后不承诺自动唤醒。
