# 执行协作

授权以 [方案与授权](feature-design.md#唯一授权规则) 为唯一依据；本文件只规定执行方法。主控和子代理均须按实际仓库工作，不把通用规则替代项目规范。

## 各仓库规范加载与落实

从用户路径、当前目录、有效记录或宿主项目清单核实工程身份，不从截图猜路径。记录各仓库分支/提交、已有改动及必要文件基线。命令明确工作目录，工具与 MCP 能力实际核验，不假定跨仓库共享配置。

执行者自行读取目标路径适用的上级、根目录和子目录 AGENTS.md 及相关语言工程规范。主控摘要和历史代码不能替代规范；同一执行者已读且未变化的内容无需重复加载。进入新路径或规范变化时补读。引用缺失或冲突先核查，只暂停确受影响的部分；不声称读过缺失资料。

仅记录影响当前变更的约束与来源。具体架构、类型、注释、文件组织和工具链属于项目，不复制进通用 Skill；旧违规不构成例外。

## 只读核查与任务关联性

涉及方案正确性的现有接口、配置或数据库事实，应在请求实施授权前完成必要的只读核查；不能只把尚未做的检查写为“实施后再核实”。优先复用仍有效的证据，范围限于目标行为及直接依赖，不扩大成环境巡检。

数据库优先使用已配置 MCP；没有可用 MCP 不等于数据库不可连接。继续核对项目实际开发配置、环境覆盖和已有连接记录，并使用现有可用客户端或驱动尝试最小只读连接；核对目标身份、相关表字段、索引及必要迁移状态。凭据只在本地使用，不输出到日志、文档或命令回显。目标不明确、缺凭据或需新增工具时先说明具体缺口，不猜测生产目标、不擅自安装依赖或绕过访问限制。

严格区分“尚未尝试”“尝试失败”和“连接成功但部分查询受限”。只有实际失败或明确限制才报告阻塞，并给出已尝试方式、脱敏错误、影响范围和解除条件；没有连接尝试不能宣称无法访问，也不能因写 SQL 需授权就停止已授权只读核查。读取成功后将发现回写方案、修正不成立的设计，并移除失效阻塞；只改措辞而不补核查不算解决。

只读查询不授权建表、迁移、初始化或清理数据。沿用用户保留的数据库手动执行关口，不能用测试、迁移工具或应用调用代替批准边界。证据已足够时停止，不为证明可连接而反复查询业务数据。

## 分支与运行环境

以下任务分支/worktree 默认安排仅适用于用户明确启用 `feature-delivery-workflow` 且已获实施授权的正式开发。未明确启用主技能、仅分析或编写方案、单独使用配套角色、读取或修改技能，都不触发该安排。启用边界用于防止普通任务自动切分支，不能据此把已启用工作流的正式开发改成默认使用主目录。

方案记录各仓库真实开发基线分支及提交、已有改动和交付方式。正式写业务代码前，默认创建或复用本任务独立 worktree，并使用从已核实开发基线建立的任务分支；不在主目录切分支代替独立工作树。单任务、没有并发冲突或前后端分属不同仓库，都不取消这个默认安排。跨仓库开发分别隔离各个需要写入的仓库；只读参考仓库无需创建。优先复用属于本任务且基线、改动归属适合的已有工作树，不重复创建。

主目录开发仅作为有明确理由的例外，例如用户明确要求在原目录开发，或已核实非 Git、工具限制等使 worktree 无法使用。实施前在方案中简述具体原因、为何不能采用或复用独立工作树、受影响仓库、并发/改动混入风险及保护措施；不能只写“复用主目录”。单纯为了方便、只有一个任务、主目录已有未提交改动，都不足以构成例外。必要依赖优先按下文的补丁或文件清单带入工作树；确实不能安全隔离时说明具体障碍，不能静默回退主目录。已有授权覆盖的常规隔离安排直接执行，例外涉及新增风险、授权范围或用户偏好冲突时才集中确认。

规则更新不自动迁移正在开发的任务。继续前核对当前改动和执行者，记录继续使用主目录的具体例外依据，或准备安全迁移安排；不得仅以“已经开始”作为永久例外，也不得在其他执行者仍写入时搬迁、切换目录或复制不明归属的修改。

新建手动 worktree 使用统一的仓库外根目录，**按项目、任务、仓库三级分层**，单仓库任务也保留仓库层：

| 系统 | 默认路径 |
| --- | --- |
| Windows | `E:\.worktrees\<项目标识>\<任务标识>\<仓库标识>\` |
| macOS | `~/.worktrees/<项目标识>/<任务标识>/<仓库标识>/` |

例如 Windows 的 `E:\.worktrees\Labar\supplier-review\web\`，macOS 的 `~/.worktrees/Labar/supplier-review/web/`。Windows 使用带根分隔符的绝对路径 `E:\.worktrees\`，不能写成驱动器相对路径 `E:.worktrees\`；macOS 创建前将 `~` 解析为当前用户主目录。标识简短且能辨认归属，同名冲突用稳定短后缀区分，不覆盖已有目录。跨仓库任务共用项目和任务层，各仓库分别绑定各自 Git 仓库。默认根目录不存在时可在已有任务授权内创建；磁盘不存在、不可写或用户/项目指定其他位置时，说明限制并明确替代位置，不静默退回深层嵌套目录。其他操作系统按已确认的项目约定选择位置，不套用 Windows 盘符。

**已有 worktree 不因规则更新自动搬迁。** 属于本任务且适用的已有工作树优先复用；宿主管理的工作树沿用宿主位置及生命周期工具，不强行改址。迁移须另有明确安排，先核对改动归属、服务和其他执行者，不通过直接移动代码目录迁移 Git 工作树。

任务进行期间，方案和必要交付记录放在项目 `.codex/workflows/<任务标识>/` 或用户已指定的主记录位置，记录各 worktree 的解析后绝对路径、仓库、基线及任务分支。evidence 保存在主记录中、工作树之外；收尾按 [证据与备份清理](acceptance.md#证据与备份清理) 将必要长期资料归位，满足条件后删除整个主记录任务目录。使用 Git 创建，不能用整库复制代替。

创建前确认目标归属、路径未占用及真实链接目标。仓库外目录不需要为其修改主仓库忽略规则；已有或明确指定的仓库内 worktree 仍须核查嵌套排除条件，优先本地 `.git/info/exclude`，团队共享规则遵循项目约定。两种布局均核查构建、测试、搜索和文件监听的实际扫描范围，Git 忽略不能代替工具排除；必要配置变化须纳入方案，不能静默扩大改动。

新 worktree 不带原目录未提交内容；核对归属和依赖后，仅用可验证补丁或文件清单带入必要内容。排除 `.codex/workflows`、`.git`、依赖和构建产物，避免递归复制任务目录；保留原目录，不硬重置、自动 stash 或移动用户改动。依赖优先独立安装并复用包管理器缓存，不默认联接主目录 node_modules；确需联接时记录链接路径、真实目标及清理方式。

从任务目录以独立端口启动服务，核对浏览器、代理及 API 实际指向本分支。数据库按下节规则复用现有开发库，Redis 复用已确认的开发环境；仍核实实际后台副作用不超出授权。任务代码与端口独立不代表数据隔离。记录本任务进程身份，不能停止其他任务进程或抢占端口。

**已授权的本任务开发与联调服务遇到端口占用时，自动选择空闲端口、同步任务内连接配置并继续验证，不要求用户手动换端口或启动服务。** 启动前核查监听状态与进程归属；本任务同版本且健康的服务可复用，其他任务或归属不明的服务不停止、不抢占。选择本机未占用端口，启动时若发生竞争占用，再选择空闲端口；非端口错误按实际原因排查，不能用反复换端口掩盖启动故障。

前后端端口联动处理：优先使用启动参数、环境变量或 worktree 内不纳入交付的本地配置，按实际链路更新前端代理/API 地址、任务网关及必要回调地址；仅重启本任务受影响服务。若开发服务器自动递增端口，读取其实际监听地址并同步连接方及浏览器入口。核验端口对应的进程、工作目录、服务健康与页面真实请求，确认指向本任务版本后继续联调，记录最终地址及进程；不能只修改配置就报告恢复成功。临时端口配置不回写原开发目录、不提交。

常规本地端口选择属于已有实施授权，不追加确认。用户明确固定端口、需要修改共享/生产配置、外部回调白名单或新增访问范围时，先核实影响，仅对新增范围澄清。自动端口处理不授权绕过审批拒绝；启动失败按下节区分执行阶段并处理，不能仅因端口被占用就要求用户手动执行。

### 验证与验收浏览器

页面交互、视觉验证及人工验收统一使用 **Codex App 内置浏览器**，在当前任务中提供可见页面，便于用户查看和批注。不使用操作系统默认浏览器或外部 Chrome、Edge 窗口替代，除非用户明确要求。使用浏览器工具时选择内置浏览器目标（工具提供 `iab` 时使用该标识）；打开或展示页面不等于已完成交互验证。

优先复用本任务适用的内置标签页；验证完成后按人工验收规则保留页面及服务。跨会话接管也在目标会话的内置浏览器打开或关联验收入口。内置浏览器不可用、页面无法打开或批注能力受限时，说明实际限制和未验证范围，继续独立可执行的检查，不自动切换系统浏览器，也不声称已提供可批注的验收现场。

### 服务启动诊断与恢复

启动前核对项目约定的启动命令、工作目录、必要配置来源及当前工具权限。优先复用本任务同版本且健康的服务；需要启动时保留可追踪的进程或终端身份及日志位置。Windows 后台启动使用隐藏窗口，除非用户要求可见交互窗口。不把某种 sandbox/approval 组合或某个启动器写成项目启动的固定前提，不修改全局安全配置来恢复服务。

失败先按实际执行阶段定位，不将所有现象统称为“项目无法启动”：

| 阶段 | 必要证据与处理 |
| --- | --- |
| 命令未获执行 | 保留完整命令、工作目录、工具返回及已提供的审批理由，敏感参数脱敏；检查当前权限和正式申请能力。不能将工具拒绝当作应用启动日志或代码故障 |
| 进程启动后退出 | 检查退出码和启动日志，定位依赖、配置、构建或端口等实际错误；仅在已授权范围修复，不因出现启动错误就扩大业务修改 |
| 进程运行但服务不健康 | 核实进程归属、实际监听地址、健康接口及页面真实请求，排查就绪状态和连接配置；有进程或返回页面 200 均不能单独证明业务链路可用 |

**业务授权与工具权限分别核对。** 已授权的启动操作如需额外权限，且当前宿主允许申请，使用其正式审批或权限申请机制，提交具体命令、工作目录、必要路径/网络范围、用途及实际影响，申请最小必要权限；不重新索取已有业务授权，也不将业务授权等同于工具已放行。当前策略不允许申请时，不发送不支持的提权参数，明确缺少的能力和可行的解除条件。

**正式审批不是绕过拒绝。** 实际审批拒绝后，按返回理由检查是否存在合规的更安全方案，或可补充证明授权与风险的证据；仅在宿主规则允许且有新依据时通过正式机制重新申请，不盲目重试。不得为规避拒绝换 shell、改写脚本、包装同一操作或切换到另一个执行工具。无法安全继续时，单独说明被拒绝的动作、审批返回的理由及仍需用户处理的事项；其他独立已授权工作继续。

仅有通用拒绝信息时标明“具体命中规则未知”，不猜测为 `never`、`Start-Process`、自动审批或 Windows 拦截导致。当前权限状态不能倒推历史状态；重新执行成功只证明本次条件下成功，不证明旧拒绝的具体原因。不要求用户提供凭据，也不为追因收集无关日志或敏感配置。

恢复后核验本任务进程归属、服务健康及受影响页面的真实请求，记录有效启动方式、配置来源、实际地址和验证范围，然后继续原任务。旧拒绝原因未明但已不影响当前工作时，保留该缺口，不将历史追因继续列为启动阻塞；用户明确要求追因时单独查证，不混淆“服务已恢复”和“旧拒绝原因已查明”。

正式业务开发向开发基线整合前，必须满足 [人工验收关口](acceptance.md#工程完成与人工验收)；文件复制、补丁应用及增量回写与 Git 合并受同一关口约束。

合并默认回到已核实的开发基线，不用当前恰好检出的分支代替。方式沿用仓库约定；无约定时保留历史，能快进则快进，否则普通合并。不为常规分支和方式重复提问，有歧义或影响其他工作时才集中处理。

## 数据库环境

数据库验证默认使用项目现有、已确认的开发库。先从配置和已有记录核实连接目标、实际结构及迁移状态；目标不明确时先只读核查，无法核实才询问用户。不因创建 worktree、并行开发、测试方便或环境缺口，自行新建临时数据库实例、测试库、Schema 或数据库容器；另建数据库环境仅在用户明确要求或确认具体安排后执行。没有可用开发库时说明实际阻塞并继续独立工作，不以隔离库替代真实联调。

数据库变更 SQL 由用户手动执行：包括建表/改表、迁移、字典/菜单初始化、经专门授权的历史数据修复及直接清理测试数据的 SQL。手动执行要求不是允许补造验证数据的授权；缺数据须先按 [缺数据先查业务链路](acceptance.md#缺数据先查业务链路) 查因，真实联调数据必须通过正常流程产生，不能让用户执行补数 SQL 绕过该规则。代理负责只读核查、准备和审查合规脚本，不通过终端、MCP、迁移工具或测试初始化代码代为执行，也不能将这些操作包装成应用调用绕过手动执行要求。正常业务接口验证仍按已批准范围进行，不据此扩大数据修改权限。

交付执行材料时，写清目标环境和库、完整 SQL 文件与确切批次、顺序、影响对象、重复执行限制、核验查询及必要恢复方式；正文保留关键摘要，长 SQL 提供可点击完整文件，不以省略内容或只报批次名代替可审查脚本。

材料就绪后，必须用可用的用户输入工具弹框询问“是否已在指定环境执行完所列 SQL”，提供“已全部执行完成”“尚未执行”“部分完成或执行失败”等清晰选项。优先使用 request_user_input_async；仅在工具实际可用的模式下使用 request_user_input。弹框中标明具体目标、脚本/批次和完整文件入口，确认的是用户已经执行完成，而不是授权代理执行。工具不可用时在聊天中明确询问并等待，不声称已弹框。

用户未回复、尚未执行或部分失败时，不运行依赖这些变更的启动、联调、数据库测试或后续迁移；可以继续不依赖它们的已授权工作。超时、预选选项或“允许执行”均不等于“已执行完成”。用户明确确认后，记录实际环境和完成范围，进行必要只读核验，再继续后续步骤；失败先核实结果，不代为重跑。脚本内容或执行目标变化后，只对新增/变更部分重新确认。该确认是用户保留的执行关口，不因整体实施已授权而跳过。开发库数据准备与测试限制见 [开发环境测试数据与菜单](acceptance.md#开发环境测试数据与菜单)。

## 分派与并行

角色不是固定团队人数。前后端或其他任务具备独立输入、写入边界且工具允许时并行；小任务由主控承担。默认聚焦一个功能不等于一个执行者。不同仓库不必独立，同仓库也不必串行；共享文件、构建目录及会相互干扰的运行资源指定唯一写入或操作负责人。

区分开发依赖与联调依赖：契约明确后可独立实现的部分先做；运行接口、实际 Schema 等条件只阻塞依赖它的接入或验证。项目强制的契约核验前置条件须遵守，不借 Mock 绕过。契约可核对就及时交接，不等待无关测试；文档就绪不等于真实业务可用。

简报给出目标、目录、角色 Skill、项目规范路径、有效方案及授权依据、原有改动、写入边界、依赖和完成条件。子任务不递归组建工作流，不能凭别的案例猜本任务。角色交接只报告有变化的事实及证据，主控维护公共记录。

只要操作互不干扰即可并行，不要求数据库实例物理隔离。共享浏览器、可冲突的账号/数据、构建输出和 Git 写操作由唯一负责人处理。审核和行为验证可在明确版本上并行；代码变化只使受影响证据失效。

独立侧栏会话仅在用户明确授权后创建或发消息，内部代理授权不能替代。使用实际工具能力，通知送达与执行完成分开核实；失效任务 ID 不反复联系。

## 执行效率

- 读取从当前差异和目标入口开始，用定位后的片段覆盖直接依赖；已读取且未变化的规范、文件和契约不反复全量输出。版本或事实发生变化才补查，不能以节省上下文省略必要链路核查。
- 完整构建日志和大型工具结果保存在任务记录位置，聊天与角色交接仅返回结论、关键错误、受影响范围和证据入口。可限量或筛选的工具结果先收敛后输出，不把整个检索结果、旧会话或全部日志搬入主上下文。
- 同一行为链集中实现和验证，复用同版本且仍适用的证据；只有新改动、失败、环境变化或证据缺口才追加对应检查，项目强制检查仍执行。不因换会话或角色重复全量测试，也不能将旧版本通过套用于新代码。
- 开始时最小核查服务、文档与构建条件，不默认全量构建。隔离目录和可靠缓存可复用，变化时核对版本，不反复复制整库。
- 确需清洁构建时先核对服务/构建进程对输出目录的占用；确认本任务身份和无后续依赖后停止并核实退出，不按进程名批量终止。有效构建证据仍适用时不为收尾再次 clean。
- 同一输出目录由一人构建，其余执行者复用有效证据。等待优先完成通知或带游标的状态等待；需查询时拉开间隔，仅取新增输出或末尾关键错误，不频繁读取相同日志。状态未变化不重复播报；耗时异常区分有效推进、失败和停滞，不任意限时中断。
- 准备提交时可并行：主控核对证据和简短交付记录，子代理只读核对文件归属、基线、目标变化及冲突风险。主控在人工验收通过或明确免除后，按已确认方案统一串行暂存、提交、合并、推送、远程核验和清理，不逐项再次申请授权；写操作前核对版本未失效，清理须满足[合并后先推送再清理](acceptance.md#合并后先推送再清理)的条件。不为小任务强制新增代理。

## 会话拆分与上下文交接

**按交付目标拆分，不按聊天长度机械拆分。** 当前功能的实现、联调、必要验证和原需求验收缺陷由当前会话闭环。已完成后的独立体验优化或新功能适合新会话；技能、流程与文档风格维护建议独立处理。多目标混杂、反复恢复旧决策或长日志挤占当前工作时，可在安全停点建议续开；没有准确用量数据时，不声称节省了具体 token 或比例。

**准备交接不等于停止执行或获得建会话权限。** 用户尚未明确要求转移时，继续已授权当前工作，不以会话变长为由留下未完成项。只有用户明确授权新建会话才调用创建工具；向已有会话发消息也需用户授权。已明确授权同一次创建或通知则直接执行，不重复申请。工具不可用时交付简短启动文本和记录入口，不虚构后台交接。

**以减少历史负担为目的时，新建干净会话，不默认分叉。** 分叉保留原历史。新会话读取精简交接、适用项目规范及本次相关文件，不先通读旧聊天或重新加载整套角色材料。只有缺失关键事实、授权证据或出现矛盾时，定向回查对应消息或文件；回查不到就保留缺口，不能把摘要的“已授权”视作充分证据。

交接优先更新既有主记录中的“当前交接”小节，另开长报告不是要求。以一屏摘要为目标，必要证据用路径和定位引用保留，不强制删掉关键边界。只维护当前结论，不追加完整过程历史；简短交接不必单独生成 HTML：

| 信息 | 最小必要内容 |
| --- | --- |
| 目标与范围 | 当前交付目标、已确认规则、本次剩余或新增任务、明确排除项 |
| 授权与验收 | 已交付方案版本与路径、用户确认的可定位依据、允许操作及限制、人工验收状态；原范围与新增范围分开 |
| 代码现场 | 各仓库与 worktree 的实际路径、分支、提交、未提交差异及归属；不只记录 HEAD |
| 完成与证据 | 已完成和剩余项；有效测试对应的代码状态、环境、结果与证据位置；失败和未验证项 |
| 运行与接管 | 各服务的工作目录、完整启动命令或脚本位置、配置来源、实际端口、进程/终端身份、健康状态及检查时间；仍运行的构建或代理、下一步最小动作、当前唯一写入负责人 |
| 浏览器现场 | 原会话ID、浏览器与标签标识（可获取时）、当前页面地址（含必要业务查询参数和锚点）、关联服务、登录是否有效及未保存输入；没有现场证据时标为未核实 |

**在安全停点交接写入责任。** 写操作、数据库事务或构建正在进行时，不直接让另一个会话接管相同文件和输出目录。由原执行者结束本轮操作并记录结果，或按用户指令暂停；先确认真实执行者状态，再转移写入责任。保留未提交改动、服务和待验收证据，不为换会话擅自提交、合并、清理或创建新 worktree。新会话接管不自动取消原任务或扩大授权；已有合法授权按 [授权交接](feature-design.md#授权交接) 延续。

新会话先做最小接管核验：路径、分支、实际差异、执行者状态及证据是否仍有效。若与交接不符，先核实差异，再继续受影响工作。同一工作区只有一个写入负责人；只读审核可以并行。通知送达、会话开始、代码完成和人工验收分别报告，不能混为“已完成”。

**续接任务时保留 worktree 和服务。** 结束本轮或创建新会话不等于任务资源可以清理。交接完成前保留原任务 worktree、分支、未提交改动、本地连接配置、运行服务及验收证据；不因换会话停止服务、删除工作树或重复建立环境。记录放在新会话可访问且不依赖待清理工作树的位置，优先现有主记录。用户已要求续接时，将资源标为“新会话仍需使用”，待无后续依赖且满足原收尾条件后再清理；不撤销已经完成的合法清理，也不无条件永久保留所有资源。

新会话核对工作树归属、当前分支及差异，继续使用这些实际路径，不默认回到主目录。服务以实际监听、进程身份和健康结果为准，旧PID不能单独证明服务仍在运行。同版本且健康的服务直接复用，不重复安装、启动或重启；已停止且需要恢复的本任务服务，在已有授权内按记录启动，端口冲突沿用本文件的自动端口规则并同步前后端连接和浏览器地址。配置只记录来源和必要非敏感项，不复制口令、令牌或私密环境变量。

**接管后在新会话打开原浏览器页面。** 交接时使用可用浏览器工具核实当前页，不能只凭旧截图或历史地址声称已核实。接管后按 [验证与验收浏览器](#验证与验收浏览器) 在新会话的 App 内置浏览器打开该地址，必要时打开多个直接相关的验收入口；已有内置标签可复用或关联时优先复用，不关闭原标签。若端口确已变化，只替换对应服务地址，保留必要业务路径、参数与锚点。打开后核验页面加载、真实请求指向本任务服务和登录状态，分别报告“已打开”与“可继续操作”。

打开相同URL不代表浏览器状态迁移：未保存表单、内存状态、弹窗及登录态可能无法自动继承。保留原标签，记录未保存状态，不能为交接自动提交表单、复制认证Cookie或导出凭据；敏感或一次性链接仅记录安全入口及恢复方式。需要重新登录或宿主不能打开/关联页面时明确具体限制并提供安全链接，不虚构浏览器已同步。新会话的首次交接反馈简述已接管的工作树、服务健康和已打开页面，不重复长报告。

## 阻塞处理

不能只列遗留项结束。核实具体原因与证据，继续独立已授权工作；可安全解除的直接处理，需要增量授权或信息时按 [授权规则](feature-design.md#唯一授权规则) 准备具体步骤与影响并明确提出，不只写“待授权”。

区分代码、文档、环境版本、工具和权限缺口；搜索不到接口不能直接推导必须部署。服务问题按 [服务启动诊断与恢复](#服务启动诊断与恢复) 判断失败阶段与正式恢复路径，不能止于“工具层拒绝”而遗漏当前可用的合规权限申请。记录已知事实、原因未明项、下一步责任、解除条件与恢复点。用户补充后核对当前状态续做，不重做仍有效项。重复故障无进展时重新定位原因；写操作结果未知先查是否生效，不盲目重试。不自行设置修复轮数或时间预算，用户已有预算才按约定处理。

恢复只核对有效范围与授权、实际代码及新改动、证据有效性、真实执行者状态和剩余最小任务。当前阻塞已解除时同步更新状态，历史原因尚未查明单独保留，不继续将已恢复事项报告为阻塞；验证仅覆盖部分链路时明确剩余缺口。无证据不得宣称完成；结束会话后不承诺自动唤醒。
