# 真实联调与多端验收

以当前功能的有效方案和实际目标端为依据。验收条件在实施前明确，完成判断在证据取得后作出。

## 先核查验收条件

核查当前构建/代码版本、运行环境、身份、测试数据、可用工具和允许的操作。测试写入、清理和外部效果须在授权边界内；启动服务为验证所需时先说明目的。项目规范决定工程检查命令和平台要求，不固定技术栈。

| 对象 | 选择工具的依据 |
| --- | --- |
| Web | 实际可用浏览器控制/自动化能力与页面访问条件 |
| 桌面应用 | 当前支持目标窗口的 Computer Use 或平台测试工具 |
| 移动 App | 可连接设备/模拟器及实际可用的平台控制能力；桌面可操作模拟器时可评估 Computer Use |
| 小程序或其他端 | 该平台开发工具、自动化或确实可用的界面控制能力 |
| 纯服务 | 可核对真实结果的接口、集成和业务测试；UI 与视觉注明不适用 |

选中 Computer Use 或其他专用工具时先读取对应可用技能及工具说明，按其限制执行。安装插件不证明目标控制能力已暴露；当前只支持浏览器时，不绕过限制操作原生 App。缺条件的验证保持未完成，可以提供人工步骤及预期结果，不能自动记为通过。

同一窗口、设备、模拟器及会互相干扰的测试数据有唯一操作负责人。先完成当前验收并交接状态，再让其他任务使用；只有环境独立才并行。

## 开发环境测试数据与菜单

在已确认的开发环境中，为已授权功能验收准备和清理必要测试数据属于本流程的默认执行范围，不再逐次申请数据写入批准。先核实环境和已有数据；现有数据足够则复用只读验证，不重复造数。需要补数据时采用最小充分的合成数据，记录本次创建的唯一标识、关联关系及清理方式；不得修改原有业务数据、覆盖同名或同 ID 记录，不得触发实际发布、审批或其他未授权外部效果。共享开发环境适用同样规则，不能仅凭使用共享数据库就重复询问。

准备、浏览器/接口验收及清理连续执行。清理只针对本次记录的测试对象，执行前核对归属、预期状态及新增关联；若已被他人修改、引用或无法确认安全删除，只暂停受影响清理并说明具体原因，不扩大删除范围。完成后核验测试数据清理结果与原有业务数据未受影响的证据。合成数据验证不冒充真实发布、审批流程验证；可能触发这些流程或环境身份不明时先解决具体缺口。

菜单属于已确认功能范围时，按项目方式直接落实并验证，作为正式配置保留，不混入测试数据清理。先核实是否已存在，避免重复新增；不顺带修改角色授权或无关菜单。菜单范围不明或需扩大权限时仅澄清该项，继续其他已授权验证。

本规则不授权生产环境写入、修改既有业务数据或数据库结构变更；这些操作遵循各自具体授权。用户后续明确限制测试数据操作时以最新指令为准。跨代理或会话交接时明确传递上述已授权范围，不再沿用已被用户更新的旧确认要求。

## 验什么、留下什么证据

实现后的代码审核使用 [代码审核角色](../../project-code-review/SKILL.md)，核对实际代码及验证有效性；本文件负责跨端验收结论，不重复角色检查清单。问题交回 [开发实现角色](../../project-implementation/SKILL.md) 在有效授权内修复，主控核对复核证据后关闭问题。

验证范围、测试执行和缺陷复测使用 [测试与验证角色](../../project-test-validation/SKILL.md)。开发自测报告作为输入，测试角色核实证据并补齐必要缺口；代码审核结论不能代替实际行为验证，已有效通过的检查不因角色切换重复执行。

| 维度 | 按实际风险选择检查 | 证据应说明 |
| --- | --- | --- |
| 工程检查 | 受影响测试、类型/编译、项目规定构建等 | 命令、目录、版本、时间、实际结果；跳过与失败单独记录 |
| 项目规范 | 按各仓库适用规则核查实际新增、修改、删除或移动的内容 | 规则来源、变更位置、自动或人工检查结果；违规及未覆盖项明确记录 |
| 真实联调 | 请求/响应映射、结果持久化或可信读取、状态和必要副作用 | 环境、路径、脱敏输入输出与最终结果；与当前约定是否一致 |
| 功能 | 当前交互、成功、关键失败及边界 | 目标端、前置条件、操作、预期、实际、证据与结论 |
| 视觉 | 当前界面的布局、层级、关键状态及平台适配 | 参考依据、可比条件、实际画面及差异 |

对新增/变更接口核对生产者和调用方；重复、并发、异步等检查只在真实行为或风险存在时要求。异步操作区分请求接受、业务完成及外部影响。不得以模拟测试、打包成功或源码检查替代产品实际结果。

有设计参考时保持视口、状态和数据条件可比；没有原型时依据已确认设计或现有产品规范，不宣称“像素还原”。功能通过和视觉符合分别评价。当前无视觉变化时给出不适用依据，不为减轻验证把相关视觉要求标不适用。

## 逐端结论与完成门槛

每个实际相关端分别记录：项目规范、工程、Mock（如使用）、真实联调、功能、视觉。取值使用“通过 / 失败 / 未验证 / 不适用”，均附证据或原因；阻塞另说明所缺条件及下一步。

交付前主控以本次变更相对实施基线的实际差异核查规范，包含未跟踪的新文件，不只检查截图或抽象方案。有项目现成检查工具时按要求执行；分层、职责、注释完整性、类型及 SQL 组织等未被工具覆盖的适用规则须人工核对。只检查受影响范围，不借机整库格式化或修复历史问题。违规须给出规则来源和位置，在有效授权内修复并复核；超出范围的变更先说明方案。编译、测试通过不能推导规范通过；存在未解决的强制违规时，不标整体已验证。无问题时简述结论和范围，不复述整份规范。

Web 通过不能替代 App 通过；一个接口就绪不能替代其他接口就绪。角色给出的报告先核对适用范围与时效，不能仅依据“已完成”三字升级状态。

标记当前功能已验证需满足：已确认范围实现或有复用依据、当前契约一致、必要工程与真实联调检查通过、各相关端适用功能和视觉检查通过、影响完成条件的问题已解决。缺必要环境时报告“实现与已验证部分、剩余验证”，保留待办；代理验证与用户人工接受分开。

交付说明本次实际范围、关键证据、与方案的实质差异、未验证/失败/遗留事项及后续功能。范围内问题交回负责角色修复，只复验相关路径和必要回归；不删除失败记录或放宽标准获得通过。

## 收敛规则

实施计划包含自动提交合并时，按 [分支与运行环境](coordination.md#分支与运行环境) 核实约定审核测试条件、证据所对应版本及开发基线，默认合回该基线并沿用仓库合并约定，连续完成已授权操作并验证结果。代码检查通过但必需真实联调未完成时，不提前合并；已有失败是否不影响合并须有适用依据，不能自行豁免。未取得合并授权时集中补齐；目标与方式优先自行核实，仅有歧义或影响其他工作时询问，不把阶段性结果冒充全部交付。

必要审核、受影响行为验证及项目强制检查完成，且影响当前完成条件的问题已解决后，立即进入交付。只更新现有记录中的结果、必要证据链接和剩余项，不为收尾另建重复报告、重跑有效检查或扩大无关排查。快速且有价值的测试不因用例数量多而删减；优化依据实际耗时和重复成本。

主控复用已核实且覆盖当前版本的审核与测试证据，重点检查遗漏、版本一致性和剩余条件，不再完整执行各角色已完成的工作。新增变化、失败或证据缺口才触发针对性复核与复测，不能以“及时收尾”跳过必要验证。

收尾前逐项判断剩余必要工作：已授权且可执行的继续完成；需要新增授权或缺少必要信息的，按 [阻塞处理](coordination.md#阻塞处理) 准备具体步骤和影响，并明确向用户申请授权或询问缺失信息。不能只列“数据库未执行、未部署、待联调”等遗留项就结束，也不能用代码实现完成替代原目标完成。

仅剩已核实的环境、授权或外部依赖阻塞时，才结束本轮可执行工作，报告部分完成或阻塞，保留恢复点与下一步责任；不标记整个功能验收完成，也不默默取消未完成项。用户明确暂停、缩减范围或只要求阶段性交付的，遵循其指令并准确标注交付边界。

## 页面追踪与修复闭环

验收资料沿用需求文档的原型页面目录及已采用的审查分组，不另造一套分类；每个审查单元关联需求、用例、缺陷和证据，并保留来源页面链接。工程检查通过后再执行实际环境业务流程测试及适用界面探索、视觉检查，分别记录结果。Web 可使用实际可用的 Playwright 等能力，其他端按上表选工具。

失败先保留证据并区分实现、契约、环境、需求或视觉问题。在已授权范围及约定修复预算内定向修复和复验；准备阶段明确适用的轮次、时间或成本限制，不自造用户已批准的预算。超出预算、反复无进展或涉及重要新决策时给出具体缺陷及选项，交用户决定继续、调整或暂停；保持有效进展记录。

自动验证满足条件后生成与需求组织一致的追踪与验收结果，提交用户最终验收。人工不通过的意见回到对应审查单元及缺陷闭环；代理不能自行标记人工通过。记录实际可取得的耗时与成本，无法取得则标未统计。聊天按 [运行记录](run-records.md) 简短说明当前阶段、当前审查项链接、下一步及必要问题和修改结果，详细报告保存在文档中。
