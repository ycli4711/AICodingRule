# 方案文档结构

## 总览与业务页面

总览列版本、决策摘要、待核实项和审阅入口。每个实际业务页面使用一份文档，页首画文字草图标出布局、字段和按钮，随后按草图的区域与子视图展开。每个区域把展示内容、数据来源与操作放在一起。取数说明范围、筛选、排序、分页以及关键字段如何计算或回退。按钮说明何时可用、触发、校验、反馈与刷新。详情、审核等有独立内容或操作的子视图在所属页面各自成节、各画草图，并列入页内目录。列表按钮写显示条件和打开行为，并链接对应小节。复杂或跨页面复用的子视图可拆为独立文档，入口直达对应章节。

## 接口与数据库

页面的取数和按钮就近链接到接口文档里的相应条目。独立接口可各建一份文档，紧密相关的接口可共用文档并设可定位标题。共享接口只定义一次。纯前端操作写明本地行为即可。

有明确数据库改动才发布数据库文档。每个相关接口在自身条目中给出改动的直达链接，共享变更链接同一条目。非接口触发的配置或迁移，从对应实施步骤链接。没有改动时，方案不显示数据库页、章节、目录入口或跳转。证据不足时在相关接口或阻塞清单写明待核实。

## 样例：班组考勤确认

| 文档 | 样例内容 |
| --- | --- |
| `index.md` | 版本、待确认事项、页面设计与接口入口 |
| `pages/team-record.md` | 左侧班组、右侧考勤及补录弹窗的草图、数据来源和操作 |
| `apis/attendance.md` | 分别定义查询、导出及补录等接口，按需要拆分 |
| `delivery.md` | 实施范围、顺序、验证与收尾 |

```text
班组考勤确认
[项目 ▾] [班组 ▾] [查询]    │ 总人数  实际出勤  异常考勤  出勤率
班组列表                    │ [姓名/手机号] [月份 ▾] [查询] [手动补录]
                            │ 考勤明细表                       [分页]
```

在右侧考勤区域的草图说明下，写表格来自当前班组和所查月份的分页结果。手动补录入口链接到补录弹窗小节。弹窗小节画草图，说明项目和班组如何回填、提交后如何刷新，并链接补录接口。

原型尚未核实具体数据库改动时，补录接口标注待核实，方案不生成数据库文档。若后续确认需要新增字段，就新增 `database/changes.md`，在补录接口内直达该字段条目，说明类型、原因、兼容和验证。字段示例只用于说明链接位置，不构成班组考勤需求。

## 样例：劳务合同审核

下例演示列表按钮与子视图的文档结构。已观察到的只有列表入口，弹窗内部待实际打开核对。草图中的待核实项是审阅占位，不能用来确认业务设计。

~~~~markdown
# 劳务合同审核

## 主列表

| 列表按钮 | 行为与对应子视图 |
| --- | --- |
| 详情 | 打开[详情弹窗](#详情弹窗)。记录适用页签与显示条件。 |
| 审核 | 打开[审核弹窗](#审核弹窗)。记录适用状态与权限。 |

## 详情弹窗

```text
┌─ 详情弹窗（结构示意） ─┐
│ 展示区域与字段待核实   │
│ 附件与底部操作待核实   │
└────────────────────────┘
```

- **展示内容**　核对信息区域、字段和附件。
- **数据来源**　核对从列表行取值还是重新查询详情。确认后在此链接对应接口。
- **按钮交互**　核对附件查看、加载失败和关闭时的表现。

## 审核弹窗

```text
┌─ 审核弹窗（结构示意） ─┐
│ 回填区与输入项待核实   │
│ 操作区及按钮待核实     │
└────────────────────────┘
```

- **展示内容**　核对回填区域、输入项和按钮。
- **数据来源**　核对回填值和提交对象来源。确认后在此链接查询或提交接口。
- **按钮交互**　核对可选动作、校验、提交成功与失败反馈，以及关闭后列表是否刷新。
~~~~

同一总览版本覆盖全部 Markdown 和对应 HTML。审阅草图与实施授权的边界见 [唯一授权规则](feature-design.md#唯一授权规则)。
