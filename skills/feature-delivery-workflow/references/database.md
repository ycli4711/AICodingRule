# 数据库与验证数据

## 数据库环境

### 方案后选择与默认值

完整方案交付后、开发开始前，展示以下数据库模式；方案中同步写明选择规则、默认值及各模式的影响。数据库模式选择与实施授权是两个独立事项，选择模式不代表批准开发。

| 模式 | 执行范围 |
| --- | --- |
| 沙盒自动执行（默认） | 在本任务隔离库中自动建表、迁移、准备测试数据和执行范围内 SQL |
| 开发库自动执行 | 在方案明确且已授权的真实开发库执行范围内 SQL |
| 手动执行 | 交付脚本，由用户在已明确的目标库执行 |

使用 request_user_input_async 提供三个选项；工具不可用时在聊天中展示。已有当前任务的明确选择或手动限制沿用，不重新计时或覆盖；用户可主动切换。未指定手动模式的目标库时先只读核实，不能自行猜测。

只有完整方案已获实施授权、且尚未选择模式时才启动 60 秒选择窗口；计时起点为实施授权与选项展示两者均完成的时刻。明确告知“60 秒未选择，将按预先授权的沙盒自动执行”，记录起止时间。等待期间可做不依赖数据库模式的已授权工作，使用可被用户输入打断的等待并核对实际经过时间，不忙轮询、不虚构超时。60 秒到期无选择，记录采用默认值后继续；依据是用户预先授权的默认规则，不是把沉默或预选选项当成新授权。没有实施授权不计时、不自动开工；不得用此默认值通过其他待确认事项。工具无法继续等待时保留待选状态，不承诺后台自动执行。

用户在等待中选择则立即结束等待。后续要求切换时先暂停受影响写入，核实目标及新增影响；已执行的内容不自动撤销或迁移。新目标或操作超出既有方案授权时申请实际增量，不能仅凭模式选择扩大权限。接手时沿用已记录的选择、授权及计时，不重复开启窗口。

### 环境与执行边界

沙盒指可核验隔离的本任务数据库实例、数据库或 Schema，不是终端工具的权限沙箱，也不是独立 worktree。使用现有工具建立或复用任务专属环境，记录连接目标、归属及清理范围；从项目迁移与结构定义初始化，不自动复制真实业务数据。核实应用和迁移连接确实指向沙盒，并隔离会写入共享系统的服务、队列或外部副作用。缺少运行时、权限或无法证明隔离时说明具体阻塞，继续独立工作，不擅自安装依赖、绕过工具审批或切换真实开发库。

开发库模式先从配置及已有记录核实真实连接目标、结构与迁移状态；自动执行仅覆盖方案已明确并获批的对象、SQL 变更和影响。生产操作、清空共享数据、不可逆删除真实数据及范围外变更须有专门明确授权，不能由默认值或泛化自动执行授权推导。只读核查不授予写入权限。

执行前交付可审查的完整 SQL 文件、目标库、批次、顺序、影响对象、重复执行限制、核验及必要恢复方式。自动模式在已有授权内执行，不逐条询问 SQL；执行后记录实际目标、批次和结果并核验，失败或结果未知先查实际状态，不盲目重跑。脚本保存、方案批准或命令返回均不能代替成功核验。

手动模式下代理不代执行 SQL。材料就绪后通过可用用户输入工具询问指定目标和脚本是否“已全部执行完成／尚未执行／部分完成或执行失败”，附完整材料入口；无工具时在聊天中询问。未回复或未完成时只暂停依赖步骤，超时不算执行完成。收到完成确认后只读核验，再继续；目标或脚本变化仅核对相应增量。

数据库模式、目标、授权依据、选择或默认生效时间、执行及核验结果写入同一当前记录。沙盒验证不能报告为真实开发库已变更或真实联调通过；交付分别列明已执行环境、未执行环境及后续部署迁移事项。

## 归档时的数据库交付状态

沙盒或任务归档前，按最终交付范围核对数据库变更及执行证据；在归档完成或部分完成的聊天回复中主动列出“数据库交付状态”，不能仅埋在归档文档中，也不能等用户追问。代码合并、推送和 SQL 文件归档均不代表目标数据库已执行。

| 状态 | 使用依据 |
| --- | --- |
| 有待执行 SQL | 已核实指定目标环境缺少对应变更，列明待执行批次 |
| 已执行并核验 | 有该目标环境、对应批次的实际执行与只读核验依据 |
| 本次无需执行 SQL | 已核对本次无结构、配置数据或历史数据迁移需求，简述依据 |
| 目标环境尚未核实 | 存在迁移需求但目标或执行状态未核实，不能写成无需执行或已完成 |

有 SQL 时按实际目标环境分别说明：服务及库/Schema 的可识别名称（不含凭据）、状态、正式脚本链接与最终迁移编号、前置依赖、执行顺序、已执行/待执行范围及重复执行限制。简记执行方式、核验入口和必要恢复说明，完整 SQL 与操作细节链接正式文件；菜单授权、审批配置等非 SQL 配套事项单列。共享开发、测试或生产环境尚未核实时如实标记，不为归档扩大访问范围；沙盒已执行不能推定其他环境已执行。仅供沙盒初始化或测试造数的 SQL 与正式迁移分开，不能要求目标环境照搬。

清理前按 [证据与备份清理](closeout.md#证据与备份清理) 保全正式迁移/恢复脚本及执行说明。以最终合并或回写版本核对脚本路径、编号、依赖和说明，修正旧编号与失效引用；不整份重跑含历史批次的升级脚本。长清单可链接，但聊天仍须明确是否有 SQL 待执行、已核验环境及未核实范围。

归档只交付状态和后续事项，不自动执行目标环境 SQL、不切换数据库模式或扩大授权。已有明确执行授权和任务必需迁移仍按 [数据库环境](#数据库环境) 完成；不能通过归档把未完成的必需执行步骤改成已完成。其他环境待迁移不阻止已获准的沙盒归档，但须保全材料并明确代码交付与目标环境可用状态的区别。

## 开发环境测试数据与菜单

数据库环境遵循 [数据库环境](database.md#数据库环境) 的当前任务模式。运行数据库测试前检查初始化、清理和迁移脚本；不得把带删库、重建业务表、全表清空或无范围删除的隔离测试直接指向开发库。测试数据仅限本任务可识别且可安全清理的记录；无法满足时调整用例或报告该项验证缺口，可在已授权沙盒内进行隔离测试，不为测试通过破坏开发库原有数据。

已确认开发环境中，现有数据足够且来源符合验证目标时只读复用；新增真实联调或验收数据必须按下述“缺数据先查业务链路”规则，通过已授权的正常业务流程产生。记录数据来源、操作路径、唯一标识、关系、状态和清理方式；不得以合成数据授权修改既有业务数据、覆盖冲突 ID 或触发未授权的发布、审批等效果。

准备、验证、清理按交付阶段推进；正式业务开发默认保留验收所需数据至用户明确验收通过，或明确免除人工验收且满足其他收尾条件后再清理。删除前核对归属、预期状态和新增关联。已被他人修改/引用或不能安全删除时只暂停该项清理并说明，不能扩大删除；结束后验证清理结果及原有数据未受影响的证据。直接清理数据的 SQL 按当前模式自动或手动执行；沙盒清理只限核实归属且不再用于验收的本任务资源；清理授权不包含补造或改写业务事实。

### 缺数据先查业务链路

1. **先查为什么没有产生数据。** 沿目标数据的业务生产入口、前置条件、权限、审批、状态流转、事务写入和关联关系做必要只读核查，区分流程尚未操作、生产链缺陷、上游能力未实现、历史数据异常和测试种子。已有数据是否满足验证，须看业务来源和状态，不只看表中是否有记录。不能直接把“缺样本”解释成需要补数。
2. **用正常流程产生验证数据。** 真实联调及业务验收必须通过正常页面操作或等价的公开业务接口完成所需步骤，保留身份、校验、审批、状态流转及事务约束。调用业务接口不能跳过待验证的上游步骤；验证页面交互时也不能只用接口成功代替页面操作证据。测试名称、备注等输入可使用可识别的测试标记，但轮次、资格、审批结论、发布状态、关联关系、附件和提交时间等业务事实必须由对应正常流程产生，不得直接插表、改状态、手工拼关联或伪造附件补齐。
3. **流程不通就处理根因。** 生产链有缺陷时，在授权范围内修复入口并从正常操作复验；上游未实现、前置条件或权限不足时，说明具体缺口及影响，超出范围则先申请增量方案授权。继续独立可验证部分，将受阻部分如实标为未验证；不得为了让测试走通增加测试专用写库入口、跳过审批或补造业务事实。
4. **合成数据授权不包含伪造业务过程。** 获批沙盒内允许直接准备标明来源的合成 fixture；真实开发库仍仅通过已授权的正常流程产生验证记录。离线或隔离测试替身只支持相应局部结论，不证明真实业务链路已完成；沙盒内若验收完整流程，也须通过正常业务入口产生过程证据。历史种子数据不得冒充真实提交、审批或发布证据，也不得补字段使其看似经历过完整流程。
5. **历史修复与验证准备分开。** 只有业务上确实需要恢复历史记录，且已查明根因、历史事实有证据，才提出独立的数据修复方案，说明目标记录、事实依据、影响、核验与回退并取得专门授权。没有历史业务事实不能用回填制造它；需要 SQL 的按当前模式及专门授权执行。SQL 执行完成只证明数据已写入，不使补造数据成为合法验证依据，也不能把历史修复包装成继续联调的必经步骤。修复结果与正常流程验证分别报告。

已确认功能范围内的菜单直接按项目方式落实，先查是否已存在，作为正式配置保留，不随样例删除，也不顺带修改角色权限或其他菜单。结构变更、既有数据修改、生产操作等按统一授权规则处理。
